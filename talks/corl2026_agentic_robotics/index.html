Built and saved by the agent

  • geometry helpers — pixel → 3D point, rotation math
  • a planner that keeps earlier decisions — e.g. the 45° waypoint after a refused rotation
  • a skill file — steps, checks, lessons from failed motions

Still decided by the model

  • which targets to pick in the image
  • how the fingers make contact
  • what to do with feedback — retry a failed lift, re-locate the basket

What our experiments show

Coding agents, with the large models underneath, can tackle some robotics tasks.
But three issues remain:
01

Time

slow steps; the robot waits for the model

02

Safety

sees danger, doesn't stop; no undo

03

Motor skills

no reliable motor-level skills to call

19

Model latency cannot set the control rate

● VLM / ◆ decider: 1 / end-to-end latency · ◇ agent step: 1 / step time · △ policy: command or loop rate (Fast-WAM: 1 / inference latency)

Coding task

the world waits · many attempts in parallel

Robot task

the world keeps moving · one body, one thread

Model latency: OpenRouter, average end-to-end latency, best provider, past week (Nov 11, 2026).
20

Safety needs a local response

Coding task

  • git revert
  • mistakes caught before they matter

Robot task

  • no undo
  • asked to retract 48 s after noticing high force
  • stopping must happen in milliseconds — without waiting for the model
